# Montavar → Stelux parity ledger

Status: **implementation and comparison in progress; exact parity is not established.**

Reference: https://montavar.websonik.nl/dashboard/index.php

The user explicitly requires the original to remain unchanged. Only read-only navigation, DOM/form inspection, screenshots, and client-side diagnostics have been used on the live site. No source forms were submitted, no Generate/reset/refresh actions were triggered, and no live records were created, edited, deleted, imported, or exported. The original tab was returned to the IPO - Carry Over Management Dashboard after inspection.

Only the logged-in live app is available. The user confirmed that there is no source-code access or separate writable test copy. Hidden PHP calculations, database triggers, and mutation side effects cannot be proven by the current access.

## Deliberate pilot-boundary crossings

Inside a pilot the other pilot's records are refused (hosted profile). Exactly two places cross that boundary on purpose, each in one named server function with tests in `tests/access.test.ts`:

1. **Isometric summary** (`isoSummariesFor` in `server/iso-summary.ts`): per visible isometric, progress, quality, blocker counts per group, list flags and KPI facts computed from every record, delivered with the workspace data in both pilots. Aggregates only, never a weld, result, welder or material line.
2. **Copy isometrics parts** (`copyParts` in `server/release-access.ts`): welds, materials and calculations are each checked with the account's profile in the pilot that owns them.
