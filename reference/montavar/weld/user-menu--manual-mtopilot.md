## Chapters (rules in own words)

### 1. Introduction
- MTOPilot is the material take-off application of the WSAPPS suite; it covers the material life cycle of piping projects on a site: take-off per isometric, ordering, receiving, free-pool inventory, storehouses, transfer orders, spool/material transport, laydowns, service requests, certifications.
- Concepts table: MTO (list of materials an isometric needs); Operation phase (life-cycle stage of a material on an ISO: ordered, received, picked, installed); Free pool (site stock that can be assigned/picked); Storehouse (Lager) (physical warehouse with its own balance per article/charge); Transfer Order (STO) (stock move between storehouses, tracked with notifications); Laydown (staging area for spools/materials); Service request (request to a service company to treat/transport — painting, chemical cleaning, PWHT); Readiness (dashboard concept: startable, partially covered, blocked, waiting on orders/backorder).
- Access needs the "mtopilot" application permission and a valid project site.

### 2. Getting Started
- 2.1 Log in: open the MTOPilot URL; if not logged in you go to the shared login page and return after login. A "no permission" alert means the account lacks the MTOPilot application right.
- 2.2 Choose a project site: the app is site-scoped. With no site chosen an info alert "Choose project site" appears and the Choose project site dialog opens (pick site, confirm). Later: user name (top right) → "Change site"; the page reloads and all pilots' site sessions are synchronised. The active site is a badge in the header.
- 2.3 Header table: MTOPilot® + site badge; topbar menu toggle (switch module); language selector (NL / EN / DE); expire warnings (personnel document expiry — off by default in MTOPilot); notifications bell (unread count, recent notifications of Transfer Orders and PDF jobs, "Mark all read" clears the badge); theme toggle (light/dark); user menu (site selector, language, Logout).
- 2.4 Dark mode: via the dashboard button or the header toggle.
- 2.5 Notification types → action: `sto_new` "New Transfer Order" → opens storehouse order detail; `sto_completed` "Transfer Order Completed" → same; `sto_reversed` "Transfer Order Reversed" → same; `pdf_ready` "PDF is ready" → opens/downloads the PDF job; `pdf_failed` "PDF generation failed" → no action.
- 2.6 Menu items without rights are greyed out and open the no-rights page.
- 2.7 Permission flags per page per profile (six): `s` Show, `i` Insert, `e` Edit, `d` Delete, `m` Manual / Import (manual entry and import/commit), `x` Export. The profile is evaluated against the active site and the requested page. The Administrator account skips all profile checks.
- 2.8 First-login checklist: see the MTOPilot menu groups; choose site; open Dashboard and check data loads; if ordering/receiving, check "Order & receive" rights.

### 3. Dashboard (MTO Control Panel)
- Purpose: per-site control panel of ISO readiness, shortages, backorders, not-ordered materials, with an operations board that refreshes itself every 45 seconds.
- Filters: Operation phase (dropdown from the operation-phase master data); Project / Spool / Supplier / Type (deep-link filters).
- KPI cards (click filters the board): Theoretical startable (ISOs theoretically ready); Partially covered (covered partly by inventory); Blocked isometrics (blocked by a free-pool shortage); Blocking backorder qty; Not ordered materials (unique materials not ordered); Free pool materials (positive free-pool balance).
- Visual chips: Max startable · Free pool · Ordered · Received · Open ordered · Blocking backorder · Not ordered · aging buckets 0–7 / 8–14 / 15+ days. Charts: "Isometrics by logistics signal", "Backlog by site".
- Operations board (server-side table) columns: Project / ISO (Material number in backorder view) · Readiness (status pill) · Shortage · Blocking backorder · Not ordered · Logistics / aging · Action. Quick chips: All · Startable · Partial · Blocked · Open ordered · Not ordered · At service · At laydown · Aging.
- Buttons: "Material revisions report" (generates the PDF); dark-mode toggle; auto-refresh every 45 s.
- Steps "Read ISO readiness": 1 Home → Dashboard. 2 Optionally pick an Operation phase. 3 Read the six KPI cards. 4 Use quick-filter chips. 5 Click an ISO row's action to open the isometric detail (§14).
- Steps "Find blocking backorders": 1 Click the "Blocking backorder qty" card — the board switches to backorder view (Material number column). 2 Review materials and quantities. 3 Order the material (§7) or transfer stock from a storehouse (§5).

### 4. Project Sites & Projects
- Sites list columns: Name · Address · Phone · Email · IRN Code · Options. Top bar: "Show archived sites" (toggle), "+ Add project site".
- Add a project site (steps): 1 General data → Project sites. 2 "+ Add project site". 3 Enter Name, Address, Phone, Email, IRN Code. 4 On the Iso progress tab set Shop + Field + Site (phase) to 100 %, and the active activity weights so each phase totals 100 %: Shop = Welds + NDT + Pipe + Supports + Appendages; Field = Pipe, Welds, NDT, Supports, Appendages, Punch; Site = Hydrotest + Paint/Tracing. Site activities are required only when the Site phase is above 0. 5 Choose NDT measurement: Inch-weighted or Per weld (weight unchanged; only how it is earned changes). 6 Save.
- Progress rules stated there: shop hydro/paint/punch are hidden; shop pipe/supports/appendages use a quantity on the ISO header like Field; the ceiling is Shop-typed issued / Shop MTO; Field erection uses the whole ISO; without Shop issue there is no shop handling; prefab complete is capped at Shop issued; Punch stays a separate Field weight. After saving, ISO progress is recalculated automatically; weight changes are versioned from the day of change; daily EVM snapshots feed the BBE S-curve.
- Duplicate a project site (steps): 1 Project sites → pencil in Options. 2 Change Name if wanted; the copy gets "(Copy)" after the name. 3 Open the split arrow next to "Duplicate Project site". 4 Under "Site settings" keep or clear: Project settings, Document settings, Company settings, Iso progress, ISO book (Company settings and Iso progress appear only if those features are on in System settings). 5 Under "Activated lists" keep or clear the lists to activate. 6 Click "Duplicate Project site". A ticked option copies what was enabled on the source; an unticked one leaves that category empty/default. Projects and materials are not copied.
- Click a site row → projects view `?id=<siteId>&view=projects`. Projects columns: Intern number · No. of ISO · Extern number · Description · Contact · Authority · Status · Options · checkbox. Top bar: "Options" (Delete selected, mass edit, generate books, show deleted, fill IRN); "Import all projects data" (import wizard); "+ Add project".
- Add a project: Intern number, Extern number, Description, Contact, Authority; Save.
- Mass edit projects: tick rows → Options → Mass edit. Fields as in Edit project: Intern prj. no., Extern prj. no., Contact name, Phone, Authority, Project description, Application Visibility. An empty text field keeps each project's current value; a ticked app is visible, an unticked one hidden. Click Update.
- Export projects + ISOs: "Export" downloads an XLSX.
- Import all projects data (steps): 1 Download the Excel template (full + welds): row 1 is a hint (data type), row 2 uses the labels of Edit project / Edit isometric, example rows (PROJECT 001 / 002) are included, own data from row 3. 2 Required: Intern prj. no. and Iso number. ITP Shop / ITP Field take the catalog ITP No; NoBo and PWHT are Yes/No; Type is Shop, Field or another name from the Type table; Component code 1=pipe, 2=supports, 3=appendages. Do not import Test system, X Ray %, Price or the isometric memo (Test system comes from Hydrotest release, X Ray % from the ITP). 3 Upload and review the preview: all error rows plus 100 importable rows; tick "Show all rows" for the full list; quantities rounded to three decimals. 4 Commit — every row is processed, not only the preview. 5 Then "ISO PDF Import": download "Example ZIP (2 isometrics)", upload the ZIP, check green rows, commit; open an isometric to confirm the drawing is attached.

### 5. Storehouses (Lagers)
- Section 1, search across storehouses and project sites. Filters: Storehouse / project site (multi; active storehouses and active sites only); Group / Dia / Sch (optional text, applied on Search); a text for material no, article, description or charge (at least 3 characters; without a location it matches the start of material number, article, group or charge; description is searched only inside chosen locations); "Search" (nothing loads until clicked); "Clear". Columns: Storehouse / project site · Group · Article · Material No · Dia · Sch · Description · Balance · UOM · Charge No · Certificates · Options + checkbox.
- Search rules: no search while typing; at most 200 rows shown; rows with balance zero hidden; a charge of a certification not linked to stock still shows, with the certificate and a dash instead of balance; a storehouse row is stock in that storehouse; a project-site row is that site's free-pool balance (same as Order & receive → Inventory) with Charge No/Certificates from that site's certifications; transfer, move, return and the checkbox exist only on storehouse rows; a project-site row opens its certificates only.
- Steps: 1 General data → Storehouses. 2 Choose locations or type 3+ characters (archived sites are not searched). 3 Optionally Group/Dia/Sch. 4 Search. 5 Read Balance, Charge No, Certificates. 6 If over 200 rows, narrow. 7 Storehouse row: checkbox + "Transfer selected". Site row: certificate button.
- Section 2, storehouses list: columns Name · Location · Options. Top bar: "Transfer selected" (start a transfer of the selected stock), "+ Add" (Add storehouse: Name, Location; Save).
- Storehouse detail `?id=<lagerId>`: columns Group · Article · Material No · Dia · Sch · Description · Qty · UOM · Charge No · Options + select all. Actions: "Add material" (dialog with certificate upload), "Transfer selected". Add material (steps): select material, enter Qty, UOM, Charge No, upload certificate if applicable, Save; the balance updates.
- Import storehouse stock: "Import" → download Excel template. Column `chargeno` optional; one charge may be on different material numbers; two rows with the same material number add their quantities; upload, preview, commit. Certificate PDFs go in one ZIP; file name without ".pdf" is the charge number. A charge on one material links to that line; a charge on several materials starts with every line ticked; with AI Assistant on, a document naming one material number leaves only that line ticked (other lines stay visible); adjust ticks and save the certificates.
- Create a Transfer Order from the overview: tick stock rows → "Transfer selected" → choose destination storehouse and quantity → confirm. The STO is created; recipients get `sto_new`. Track under Transfer Orders or the bell.
- Row actions on a storehouse detail: Edit item (correct group, article, description, diameter, schedule, unit after a bad import; material number stays locked; a certificate PDF can be uploaded onto the line's charge — stored, not read); Adjust quantity (set counted quantity; loss and damage lower, found raises; reason required); Remove material (hide the line after a reason; history, certificates and material number stay; blocked while an open transfer order exists); Audit trail (who changed the line: old value, new value, reason); View certificates; Print QR label.
- Material QR label: the code is the material number; if the line has exactly one charge it is printed too; the label does not name a storehouse. "Scan material" on Storehouses lists every storehouse and project inventory still holding quantity; after a transfer or return the same label shows the new place. "Start transfer" on a found location opens the order for that material from that place: from a storehouse choose Storehouse → Project, Storehouse → Storehouse or Return → Inventory; from the current site's inventory choose Inventory → Project or Inventory → Storehouse. Several ticked rows + "Print labels" prints one label per material number.
- Modal field tables in the manual:
  - Transfer to project: Material (read-only), Available (read-only), Quantity, Destination project site (archived not listed), Certificates to transfer (copied to the destination project), Transfer.
  - Move to other storehouse: Quantity, Move all, Destination storehouse, Move.
  - Return to inventory: Quantity to return, Return all, Return.
  - Edit storehouse item: Material number (shown only, never changed — it is the key for inventory, orders, certificates, transactions); Group, Article, Description, Dia, Sch, UOM (optional); Reason (required: Import error, name correction, or other); Explanation (required when reason is Other). If the number is already used elsewhere those records keep the original names; Save changes only this line and writes an audit entry.
  - Adjust quantity: New quantity (required); Reason (required: Loss, damage, found, count correction, other); Explanation (required for Other). Old movements stay, the system posts the difference; the balance cannot go below zero or below a quantity reserved on an open transfer order; only an administrator or a storehouse manager can save.
  - Remove material: Reason (required: Imported by mistake, no longer held, other); Explanation (required for Other). Remaining quantity is written off; blocked while an open transfer order reserves the material.
- Steps "Transfer storehouse stock to a project": tick rows → Transfer selected → Storehouse → Project, quantity, destination site → save the order and complete it. Each charge number receives an index number on the destination site's certifications list; without a charge the material is stocked but stays off the list.
- Steps "Move to another storehouse": tick → Transfer selected → Storehouse → Storehouse, quantity, destination → save. "Return to inventory": → Return → Inventory, quantity → save. "Review a quantity change": Audit trail on the row, or the top-bar Audit trail for the whole storehouse; read user, old quantity, new quantity, reason. The older "Correction" dialog is no longer on the row; use Adjust quantity.
- Transfer Orders (STO) list (`?page=storehouse-orders`, Transfer Orders button). Columns/filters: Order No · Type (Inventory - Project / Inventory - Storehouse / Storehouse - Project / Storehouse - Storehouse / Return - Inventory) · Priority (Normal / Urgent) · From / To · Status (Requested / Assigned / In progress / Completed / Partial / Cancelled) · Created date · Options (open detail).
- New Transfer Order modal: Transfer type; Priority; From storehouse; To project site / To storehouse (depends on type; project sites: active only); Notes (optional); Order items (Material No, Description, Qty, UOM per line). Saved STO has status Requested.
- STO detail (`?page=storehouse-order-detail&id=`) controls: "Assign to me" (status → Assigned); Qty picked per line; Line status (Pending / Picked / Not found / Partial); "Picked all"; "Save pick results"; "Complete transfer" (status → Completed, stock moves); "Print pick sheet"; "Cancel" (reason required, status Cancelled); "Reverse order" (reverses a completed STO and its stock movement).
- Steps "Pick and complete": 1 open STO. 2 Assign to me. 3 optionally Print pick sheet. 4 enter Qty picked and line status per line. 5 Save pick results. 6 when all picked, Complete transfer.
- Storehouse Transactions (`?page=storehouse-transactions`, Transactions button on the detail): each transaction has a detail `?txn=` with Report No, Date, Type, From/To, items, and "Download PDF" (opens a printable page in a new tab; use Print / Save as PDF).

### 18. Common Workflows
- 18.1 MTO on a new ISO: open ISO from Isometrics list → Materials view: add materials (existing/custom) or Import in ISO → set operation phase per material → Print MTO → dashboard and ISO execution reflect the demand.
- 18.2 Order and receive: Material order (filter, tick, Order material from list) → track under Not receive → on delivery open Receive, find order, register quantities → review in Order archive.
- 18.3 Free pool and storehouses: Inventory → New Transfer Order to a storehouse; in Storehouses add material or import stock; use STOs between storehouses and follow them via notifications / Transfer Orders.
- 18.4 Service and laydown: Spool transport → filter, tick → Service request (company, note, include ISO PDF, confirm) → when spools return, Move to laydown; track in Requests archive and the laydown detail.
- 18.5 Execution blocks: ISO execution → phase/% chip → open low-status ISO to see shortages → order or transfer → Refresh all.
- 18.6 Certificates: add per charge or import in bulk → tick Controlled/Accepted per QC → Export to ZIP per project.

### 19. Error Messages and Validation (situation → cause → resolution)
No permission → user lacks the MTOPilot application right → ask admin to enable it. No rights (page) → profile lacks Show (s) → grant on Profiles. Choose project site → no site selected → pick in chooser or header selector. Menu item greyed out → missing right, or admin-only action (e.g. Material transport Service request) → grant the right. Import failed → wrong column mapping or file format → re-download template, map, retry. Notifications not appearing → bell shows unread only → Mark all read; check per-user notifications. Expire warnings not shown → disabled by default in MTOPilot → expected. STO not completable → destination storehouse invalid or qty > balance → check balances and destination, retry. PDF generation failed → background job error → retry; check the `pdf_failed` notification.

### 20. Best Practices (12 points, paraphrased)
Choose the site first (all data is site-bound); maintain the material database centrally before bulk MTO entry; use operation phases consistently (they drive dashboard and ISO execution); order from the Material order page; receive against the correct order; use STOs for inter-storehouse moves rather than manual balance edits; refresh the materials list and ISO execution after bulk imports; import certifications in bulk and tick Controlled/Accepted during QC; use laydowns for staging; give role-3 users site-specific profiles; watch the dashboard daily for blocked ISOs and aging backorders; print reserved-materials / MTO PDFs before issuing to the field.
